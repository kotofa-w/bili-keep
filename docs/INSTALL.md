# 安装与更新

本指南适用于桌面 Chrome / Edge 的开发者模式安装。无需商店安装包，也无需 API key。

## 从源码构建

准备 Node.js >= 24，并使用 `package.json` 中 `packageManager` 指定的 pnpm 版本。在源码根目录执行：

```sh
pnpm install --frozen-lockfile
pnpm build
```

Chrome 构建目录为 `.output/chrome-mv3`，其中应有 `manifest.json`。不要把项目根目录或未解压的 ZIP 当作扩展目录。

若使用 Edge，可单独构建：

```sh
pnpm build:edge
```

Edge 构建目录为 `.output/edge-mv3`。

## 加载扩展

1. Chrome 打开 `chrome://extensions/`；Edge 打开 `edge://extensions/`。
2. 开启“开发者模式”，点击“加载已解压的扩展程序”。
3. 选择对应的构建目录，确认列表中出现 Bili Keep。
4. 刷新已经打开的 B 站视频页面，让内容脚本生效。可在浏览器工具栏固定扩展图标。

首次安装只会记录之后观察到的播放，无法从旧历史补出真实观看投入。本人互动和历史同步需要当前浏览器的 B 站登录状态。

## 开始使用

打开 `https://www.bilibili.com/video/` 下的普通视频，正常播放。点击扩展图标，再选择“打开喜好资料库”。

默认列表显示候选与已保留视频；记录较少或尚未达到候选条件时，可切换“全部”。鼠标悬停或键盘聚焦评分环可查看分数构成；点击封面、标题或“查看详情”查看依据、会话并编辑备注。“继续观看”会另开视频标签页。

在资料库页可暂停或开启自动记录；重新开启后请刷新已打开的 B 站页面。原有历史记录、分析和设置入口仍可使用。

## 更新已有扩展

1. 在资料库页“导出备份”，保存最新 JSON。
2. 更新**原源码目录**，安装锁定依赖并重新构建。
3. 回到浏览器扩展管理页，找到原有 Bili Keep，点击重新加载。
4. 刷新 B 站页面和资料库，检查记录与采集状态。

保持原加载目录和同一浏览器配置有助于沿用原扩展身份与存储。不要为常规更新先卸载扩展。

## 更换目录或浏览器

更换未打包扩展的加载目录可能改变扩展 ID 及存储空间，源码文件不会自动携带浏览器数据。

先在原扩展导出最新资料库，再在新位置加载扩展，使用“合并恢复备份”选择 JSON，检查视频、备注与手动状态。确认恢复完成前保留原扩展及备份，不要清除其数据。

资料库备份和上游历史备份相互独立：资料库页的 JSON 包含观看会话、互动快照、状态和备注；设置页的历史备份与可选云同步不包含这些新增资料。

## 常见问题

| 情况                     | 检查方式                                                                               |
| ------------------------ | -------------------------------------------------------------------------------------- |
| 无法加载扩展             | 检查构建是否成功、选择的目录是否含 `manifest.json`，以及是否开启开发者模式。           |
| 没有视频记录             | 检查自动记录是否开启，刷新普通视频页并实际播放；切换资料库筛选为“全部”，查看采集提示。 |
| 封面为空                 | 检查 B 站 CDN 网络；可信 CDN 的 HTTP 或协议相对地址会升级为 HTTPS，其他地址不加载。    |
| 点赞、投币或收藏未更新   | 确认当前浏览器已登录并稍等观察刷新；接口失败时状态可能未知，不会当作不喜欢。           |
| 更新后看不到旧记录       | 检查浏览器配置及加载目录是否改变；使用原扩展导出的 JSON 合并恢复。                     |
| 历史同步正常但资料库为空 | 两套数据分开保存；历史进度不能还原真实播放区间。                                       |

采集依赖 B 站网页结构与只读接口。隔离模拟检查不能替代真实站点验证；反馈问题时可提供浏览器版本、扩展版本和复现步骤，请勿提交 Cookie、密钥或完整个人备份。
